# Game Design Document — Space Mission Design Game

## 1. 挑戰背景

參賽項目：[NASA Space Apps Challenge 2026 — Space Mission Design Game](https://www.spaceappschallenge.org/2026/challenges/space-mission-design-game/)

官方摘要（節錄）：設計太空任務需要在任務目標、太空船設計、科學儀器、發射載具、預算、功率、質量、通訊、軌道限制之間做取捨。挑戰要求做出一款互動遊戲，讓玩家從概念到運作體驗完整任務決策，管理有限資源，並看到每個選擇如何影響任務成敗。

難度標記為 Intermediate，但同時涵蓋 Beginner/Youth，代表遊戲需要對新手友善、易懂，同時仍保有真實的取捨張力。

## 2. 核心玩法迴圈

1. 開局隨機抽出一個**場地事件**（太陽風暴、惡劣天氣等），在玩家選件前完整揭露
2. 玩家在預算與火箭酬載質量雙重限制下，挑選火箭 + 5 大類衛星部件
3. 確認組合後，播放像素風動畫：地球出發 → 穿越大氣層 → 軌道插入 → 展開部署 → 任務運作，任一階段可能失敗
4. 任務結束顯示雷達圖（6 維度）與文字總結
5. 依據特定條件解鎖成就

第一版（v1）只做**低軌道衛星（LEO）**這一種任務模板，之後再擴充其他任務類型。

## 3. 限制系統

- **雙重限制**：金錢預算 + 火箭酬載質量上限
- 火箭決定：cost、最大酬載質量、基礎可靠度
- 火箭**整台作為一個選項**，不拆成引擎/燃料箱等子部件（v1 範圍控制）

## 4. 部件目錄（v1：不精簡，維持 5 類 × 3 檔）

### 火箭（3 檔，二選一即整台購買）
| 檔位 | 說明 |
|---|---|
| 輕型 | 低成本、低酬載上限、基礎可靠度中等 |
| 中型 | 中成本、中酬載上限 |
| 重型 | 高成本、高酬載上限、基礎可靠度較高 |

### 衛星子系統（各 5 類 × 經濟/標準/高階 3 檔，共 15 個部件）
| 類別 | 影響 |
|---|---|
| 電力系統（太陽能板+電池合併） | 電力維度、運作階段電力供應 |
| 通訊系統 | 通訊維度、運作階段通訊連結 |
| 科學酬載 | 科學酬載維度 |
| 推進/姿態控制 | 軌道可靠度維度、軌道插入階段精度 |
| 結構與屏蔽 | 質量效率維度、大氣層階段結構強度、抗輻射/抗撞擊 |

## 5. 任務階段（動畫對應的 5 個檢定點）

1. **發射 Liftoff** — 火箭可靠度 vs 推重比
2. **穿越大氣層** — 結構強度 vs 應力
3. **軌道插入** — 推進精度
4. **展開部署** — 太陽能板/天線展開機構可靠度
5. **任務運作** — 電力 + 通訊 + 科學儀器是否撐過任務週期

任一階段判定失敗，動畫在該階段停止並顯示失敗原因；全部通過才算任務成功。

## 6. 隨機場地事件

- 每局開始時抽一個事件，**選件前完整揭露**，讓玩家針對性調整組合
- v1 採**單一強度**設計：不做「輕/中/強」分級，改用**更多元的事件種類**增加重玩差異
- 事件池（v1 草案，共 10 種，含 1 種基準情境）：

| 事件 | 影響階段 | 效果 |
|---|---|---|
| ☀️ 太陽閃焰 | 任務運作 | 通訊需求門檻提高 |
| 🌩️ 地磁暴 | 任務運作 | 電力需求門檻提高 |
| ☁️ 惡劣天氣 | 發射 | 可靠度需求門檻提高 |
| 💨 高空風切 | 穿越大氣層 | 結構需求門檻提高 |
| 🌠 微隕石帶 | 軌道插入 / 任務運作 | 結構需求門檻提高 |
| 🛰️ 軌道壅塞（太空垃圾） | 軌道插入 | 推進精度需求門檻提高 |
| 📡 地面站覆蓋有限 | 任務運作 | 通訊需求門檻提高 |
| ❄️ 極端低溫 | 展開部署 | 部署機構可靠度需求門檻提高 |
| 💰 預算臨時緊縮 | 選件前 | 總預算直接扣減一部分（純經濟面，不影響任何階段門檻） |
| 🌤️ 風平浪靜（基準情境） | 無 | 無特殊效果，抽中機率較高，作為對照組 |

實作時可依平衡測試調整每種事件的抽中權重。

## 7. 失敗判定邏輯

對每個階段計算：

```
margin = 玩家該項數值 − (基礎門檻 + 事件加成)
```

- `margin < 0` → 該階段**必定失敗**
- `margin ≥ 0` → 進入機率判定，margin 越大失敗機率越低，但**保留底限失敗機率**（例如 margin 很大時仍有 2%~5%），避免出現「無腦最優解」導致遊戲失去張力

## 8. 雷達圖（6 維度）

| 維度 | 對應內容 |
|---|---|
| 質量效率 | 酬載質量 vs 火箭上限的餘裕（抓剛好比例最高分，留太多餘裕不是滿分） |
| 電力 | 電力系統是否足夠支撐儀器＋通訊耗電 |
| 通訊 | 天線/收發器訊號強度與備援 |
| 軌道可靠度 | 推進/姿態控制的入軌精度 |
| 科學酬載 | 科學儀器等級與資料產出 |
| 預算效率 | 花費相對任務需求的合理度（太貴扣分，剛好夠用高分） |

## 9. 成就（v1 範例）

- 🏆 首次入軌成功
- 💰 精打細算（花費 < 60% 預算仍成功）
- 🛡️ 力抗太陽風暴（在太陽相關事件下仍成功）
- ⭐ 全能設計（六維度皆 ≥ 80）
- 💥 雖敗猶榮（於發射或大氣層階段失敗，幽默向成就）
- 🔁 屢敗屢戰（累積失敗 5 次後成功）

## 10. 美術風格

像素風（pixel art）。動畫需求：地球出發、突破大氣層、任務運作、以及各階段失敗時的對應畫面。

## 11. 範圍與時程

- 截止日：2026 年 11 月中
- 人力：主力 1 人開發，隊友非全程參與，規劃時以單人可完成為前提
- v1 範圍刻意收斂：單一任務模板（LEO 衛星）、火箭不拆子部件、事件單一強度

## 12. 尚待決定（下一步討論／技術規劃時處理）

- 技術棧（純 HTML/CSS/JS？搭配何種渲染或動畫函式庫？）
- 各部件與門檻的實際數值平衡
- 雷達圖與部件選擇畫面的實際 UI 佈局
- 像素美術資源的取得方式（自繪／素材庫／AI 生成）
