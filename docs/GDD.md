# Game Design Document — 太空精算師 Space Actuary

正式遊戲名稱：**太空精算師**（英文：Space Actuary）。「精算師」呼應遊戲核心——在預算、質量、可靠度之間精算取捨。

## 1. 挑戰背景

參賽項目：[NASA Space Apps Challenge 2026 — Space Mission Design Game](https://www.spaceappschallenge.org/2026/challenges/space-mission-design-game/)

官方摘要（節錄）：設計太空任務需要在任務目標、太空船設計、科學儀器、發射載具、預算、功率、質量、通訊、軌道限制之間做取捨。挑戰要求做出一款互動遊戲，讓玩家從概念到運作體驗完整任務決策，管理有限資源，並看到每個選擇如何影響任務成敗。

難度標記為 Intermediate，但同時涵蓋 Beginner/Youth，代表遊戲需要對新手友善、易懂，同時仍保有真實的取捨張力。

## 2. 核心玩法迴圈

1. 開局隨機抽出一個**場地事件**（太陽風暴、惡劣天氣等），在玩家選件前完整揭露
2. 玩家在預算與火箭酬載質量雙重限制下，挑選火箭 + 5 大類衛星部件
3. 確認組合後，播放像素風動畫：地球出發 → 穿越大氣層 → 軌道插入 → 展開部署 → 任務運作，任一階段可能失敗
4. 任務結束顯示雷達圖（6 維度）與文字總結
5. 依據特定條件解鎖成就

第一版（v1）只做**低軌道衛星（LEO）**這一種任務模板，之後再擴充其他任務類型。

## 3. 限制系統

- **雙重限制**：金錢預算 + 火箭酬載質量上限
- 火箭決定：cost、最大酬載質量、基礎可靠度
- 火箭**整台作為一個選項**，不拆成引擎/燃料箱等子部件（v1 範圍控制）

## 4. 部件目錄（v1：不精簡，維持 5 類 × 3 檔）

### 火箭（3 檔，二選一即整台購買）
| 檔位 | 說明 |
|---|---|
| 輕型 | 低成本、低酬載上限、基礎可靠度中等 |
| 中型 | 中成本、中酬載上限 |
| 重型 | 高成本、高酬載上限、基礎可靠度較高 |

### 衛星子系統（各 5 類 × 經濟/標準/高階 3 檔，共 15 個部件）
| 類別 | 影響 |
|---|---|
| 電力系統（太陽能板+電池合併） | 電力維度、運作階段電力供應 |
| 通訊系統 | 通訊維度、運作階段通訊連結 |
| 科學酬載 | 科學酬載維度 |
| 推進/姿態控制 | 軌道可靠度維度、軌道插入階段精度 |
| 結構與屏蔽 | 質量效率維度、大氣層階段結構強度、抗輻射/抗撞擊 |

## 5. 任務階段（動畫對應的 5 個檢定點）

1. **發射 Liftoff** — 火箭可靠度 vs 推重比
2. **穿越大氣層** — 結構強度 vs 應力
3. **軌道插入** — 推進精度
4. **展開部署** — 太陽能板/天線展開機構可靠度
5. **任務運作** — 電力 + 通訊 + 科學儀器是否撐過任務週期

任一階段判定失敗，動畫在該階段停止並顯示失敗原因；全部通過才算任務成功。

## 6. 隨機場地事件

- 每局開始時抽一個事件，**選件前完整揭露**，讓玩家針對性調整組合
- v1 採**單一強度**設計：不做「輕/中/強」分級，改用**更多元的事件種類**增加重玩差異
- 事件池（v1 草案，共 10 種，含 1 種基準情境）：

| 事件 | 影響階段 | 效果 |
|---|---|---|
| ☀️ 太陽閃焰 | 任務運作 | 通訊需求門檻提高 |
| 🌩️ 地磁暴 | 任務運作 | 電力需求門檻提高 |
| ☁️ 惡劣天氣 | 發射 | 可靠度需求門檻提高 |
| 💨 高空風切 | 穿越大氣層 | 結構需求門檻提高 |
| 🌠 微隕石帶 | 軌道插入 / 任務運作 | 結構需求門檻提高 |
| 🛰️ 軌道壅塞（太空垃圾） | 軌道插入 | 推進精度需求門檻提高 |
| 📡 地面站覆蓋有限 | 任務運作 | 通訊需求門檻提高 |
| ❄️ 極端低溫 | 展開部署 | 部署機構可靠度需求門檻提高 |
| 💰 預算臨時緊縮 | 選件前 | 總預算直接扣減一部分（純經濟面，不影響任何階段門檻） |
| 🌤️ 風平浪靜（基準情境） | 無 | 無特殊效果，抽中機率較高，作為對照組 |

實作時可依平衡測試調整每種事件的抽中權重。

## 7. 失敗判定邏輯

對每個階段計算：

```
margin = 玩家該項數值 − (基礎門檻 + 事件加成)
```

- `margin < 0` → 該階段**必定失敗**
- `margin ≥ 0` → 進入機率判定，margin 越大失敗機率越低，但**保留底限失敗機率**（例如 margin 很大時仍有 2%~5%），避免出現「無腦最優解」導致遊戲失去張力

## 8. 雷達圖（6 維度）

| 維度 | 對應內容 |
|---|---|
| 質量效率 | 酬載質量 vs 火箭上限的餘裕（抓剛好比例最高分，留太多餘裕不是滿分） |
| 電力 | 電力系統是否足夠支撐儀器＋通訊耗電 |
| 通訊 | 天線/收發器訊號強度與備援 |
| 軌道可靠度 | 推進/姿態控制的入軌精度 |
| 科學酬載 | 科學儀器等級與資料產出 |
| 預算效率 | 花費相對任務需求的合理度（太貴扣分，剛好夠用高分） |

## 9. 成就（12 個，每個都搭配一段真實太空史小知識）

- 🏆 首次入軌成功（任務成功）——阿波羅 11 號登月
- 💰 精打細算（花費 < 60% 預算仍成功）——曼加里安號火星探測器
- 🛡️ 力抗風暴（在太陽相關事件下仍成功）——1972 年 8 月太陽風暴
- ⭐ 全能設計（六維度皆 ≥ 80）——航海家一號、二號
- 💥 雖敗猶榮（於發射或大氣層階段失敗）——弗拉基米爾・科馬洛夫與聯合號一號（語氣較嚴肅，向犧牲的太空人致敬）
- 🔁 屢敗屢戰（累積失敗 5 次後成功）——SpaceX 獵鷹一號
- 🛠️ 克難精神（輕型火箭＋全經濟部件仍成功）——史普尼克一號
- 💎 不計成本（全高階部件成功）——詹姆斯・韋伯太空望遠鏡
- 💔 功虧一簣（於軌道插入/展開部署/任務運作階段失敗）——火星氣候探測者號（單位換算失誤）
- 🧯 危機處理（在「預算臨時緊縮」事件中成功）——阿波羅 13 號
- 🎯 完美無瑕（六維度皆 ≥ 95）——毅力號的「恐怖七分鐘」
- 👑 太空全才（隱藏總成就：解鎖其餘 11 個成就）

成就展示頁未解鎖時會顯示達成條件提示；已解鎖則顯示對應的太空史故事（中英雙語）。

## 10. 美術風格

像素風（pixel art）。動畫需求：地球出發、突破大氣層、任務運作、以及各階段失敗時的對應畫面。

## 11. 範圍與時程

- 截止日：2026 年 11 月中
- 人力：主力 1 人開發，隊友非全程參與，規劃時以單人可完成為前提
- v1 範圍刻意收斂：單一任務模板（LEO 衛星）、火箭不拆子部件、事件單一強度

## 12. 數值平衡表 v1

初版數值，先鎖定開始實作，等遊戲雛形做出來實際試玩後再依體驗微調。

### 基礎設定
- 起始預算：**100 Credits (C)**
- 質量單位：**MU**（抽象單位，不對應真實 kg）

### 火箭（整台選項）
| 檔位 | Cost | 最大酬載 | 基礎可靠度 |
|---|---|---|---|
| 輕型 | 20 C | 50 MU | 60 |
| 中型 | 35 C | 80 MU | 75 |
| 重型 | 55 C | 120 MU | 85 |

### 衛星子系統（格式：Cost / Mass / 主數值）
| 類別 | 經濟 | 標準 | 高階 |
|---|---|---|---|
| 電力系統 | 8 / 6 / 35 | 15 / 10 / 65 | 25 / 15 / 90 |
| 通訊系統 | 8 / 5 / 35 | 15 / 8 / 65 | 25 / 12 / 90 |
| 科學酬載 | 8 / 7 / 30 | 16 / 11 / 60 | 28 / 16 / 90 |
| 結構與屏蔽 | 8 / 6 / 35 | 14 / 10 / 65 | 24 / 14 / 90 |

科學酬載不直接關聯任何階段的成敗判定，只影響雷達圖分數——儀器故障不會讓整個任務失敗，只是科學產出變差（刻意簡化）。

「推進/姿態控制」已不是固定三檔的部件，改由下方的**燃料系統**取代，提供更多排列組合。

### 燃料系統（取代原本的推進/姿態控制部件）

玩家選擇**燃料類型**（5 選 1）與**填充量**（0~100% 滑桿），兩者共同決定質量、成本與推進貢獻值：

```
質量 = 17 MU（填充量 100% 時的基礎質量）× 填充量% × 燃料質量係數
成本 = 22 C（填充量 100% 時的基礎成本）× 填充量% × 燃料成本係數
推進貢獻值 = 90（填充量 100% 時的基礎值）× 填充量%（不受燃料類型影響）
```

質量係數 = 220（聯胺比衝，作為基準）÷ 該燃料的實際比衝，數字越小代表同樣推進力所需的質量越輕：

| 燃料 | 類型 | 比衝 (Isp) | 質量係數 | 成本係數 | 備註 |
|---|---|---|---|---|---|
| 聯胺 Hydrazine | 化學 | 220 s | 1.0×（基準） | 1.0× | 技術成熟但有毒，見下方毒氣危害處理 |
| AF-M315E | 化學（綠色推進劑） | 245 s | 0.90× | 1.3× | 比衝較高、較不毒，但較貴 |
| 雙氧水 H₂O₂ | 化學 | 160 s | 1.4× | 0.7× | 最便宜安全，但效率較差 |
| 離子推進 Ion (NSTAR) | 電推 | 3000 s | 0.07× | 1.8× | 質量效率極高但貴，且電力系統需達**標準**檔以上，否則推進值 × 0.6 |
| 霍爾推進 Hall (SPT-100) | 電推 | 1600 s | 0.14× | 1.5× | 同上，效果介於離子與化學之間 |

比衝數字皆為查證過的真實數據（見 [docs/REFERENCES.md](REFERENCES.md)），質量係數由比衝直接換算，成本係數則是反映技術複雜度的遊戲平衡數字，非物理量。

**毒氣危害處理**（僅選聯胺時出現）：加購 12 C 可完全避免風險；不加購則在模擬開始的「加註燃料」階段有 80% 機率發生工安事故，額外產生 20 C 清理成本（計入預算效率分數，不影響選件畫面當下的預算，也不會讓任務直接失敗）。期望損失 0.8×20=16 C > 加購成本 12 C，統計上加購才是划算的選擇，但玩家仍可選擇賭那 20% 機率。

### 任務階段門檻（無事件時的基準值）
| 階段 | 判定依據 | 基準門檻 |
|---|---|---|
| 發射 | 火箭可靠度 | 50 |
| 穿越大氣層 | 結構強度 | 30 |
| 軌道插入 | 推進精度（來自燃料系統的推進貢獻值） | 30 |
| 展開部署 | (電力+通訊)/2 | 30 |
| 任務運作 | 電力、通訊各自獨立判定 | 30 / 30 |

### 事件對門檻/預算的影響
| 事件 | 效果 |
|---|---|
| ☀️ 太陽閃焰 | 任務運作-通訊門檻 +25 |
| 🌩️ 地磁暴 | 任務運作-電力門檻 +25 |
| ☁️ 惡劣天氣 | 發射-可靠度門檻 +20 |
| 💨 高空風切 | 大氣層-結構門檻 +25 |
| 🌠 微隕石帶 | 任務運作新增「結構」判定（平常不檢查），門檻 30 |
| 🛰️ 軌道壅塞 | 軌道插入-推進門檻 +20 |
| 📡 地面站覆蓋有限 | 任務運作-通訊門檻 +20 |
| ❄️ 極端低溫 | 展開部署門檻 +20 |
| 💰 預算臨時緊縮 | 總預算 −20 C |
| 🌤️ 風平浪靜 | 無效果，抽中權重較高（基準情境） |

### 失敗機率曲線（margin = 數值 − 門檻）
| margin | 失敗率 |
|---|---|
| < 0 | 100%（必敗） |
| 0~10 | 25% |
| 10~30 | 10% |
| 30~60 | 5% |
| > 60 | 2%（底限，永不歸零） |

### 雷達圖計分
電力／通訊／科學／軌道可靠度四軸直接採用部件數值（35/65/90 剛好落在 0-100 尺度裡）；若任務在該數值「派上用場前」就已失敗，該軸顯示為 0，強化敘事張力。質量效率、預算效率則用「使用量 ÷ 上限」的比例計算，理想比例落在 0.85~0.95 時最高分，太少太多都扣分。

### 驗證範例
輕型火箭 + 全標準部件 + 科學選經濟檔：花費 90 C（90% 預算，落在效率甜蜜點）、質量 46 MU（輕型上限 50 的 92%，也在甜蜜點）——這是目前數值下接近最優的搭配。若該局抽到「惡劣天氣」事件，發射門檻從 50 跳到 70，輕型火箭可靠度 60 就不夠了，玩家必須改用中型火箭並壓縮其他部件預算，驗證事件系統確實會改變最優解。

## 13. 技術棧

- **純 HTML / CSS / JavaScript，不使用遊戲引擎或前端框架**，無 build 工具
  - 理由：遊戲主體是選單/表單導向（選件卡片、預算與質量計量表、結果畫面），只有一段線性動畫（火箭升空 5 階段），Phaser 之類引擎的優勢（場景管理、物理）用不太到，反而增加初學者的學習負擔
- **雷達圖用 [Chart.js](https://www.chartjs.org/)**（CDN `<script>` 載入，免安裝），用內建的 radar chart 類型，不用自己算多邊形座標
- **火箭升空動畫**：sprite sheet + Canvas 或 CSS 切換影格，對應 5 個任務階段
- **部署**：GitHub Pages，直接 serve 靜態檔案，不需要 CI/build pipeline
- 檔案結構：`index.html`、`css/style.css`、`js/data.js`（部件與事件數值，不含顯示文字）、`js/state.js`（遊戲狀態）、`js/storage.js`（localStorage 存檔）、`js/i18n.js`（中英字典）、`js/sound.js`（Web Audio 合成音效）、`js/selection.js`（選件畫面）、`js/simulation.js`（模擬判定＋飛行動畫）、`js/results.js`（雷達圖與結果畫面）、`js/achievements.js`（成就判定＋成就展示畫面）、`js/settings.js`（設定畫面）、`js/tutorial.js`（教學對話）、`js/main.js`（畫面導覽）

## 14. 存檔／多語言／音效／教學系統

### 本機存檔（localStorage，`js/storage.js`）
儲存內容：已解鎖成就清單、失敗次數、各畫面教學是否看過、設定（語言／音效開關／音量）。「重置進度與成就」只清除進度相關欄位，語言與音效偏好保留。

### 多語言（`js/i18n.js`）
中／英雙語字典，`data.js` 只存 id 與數值，顯示文字一律透過 `t(key)` 依目前語言查詢。切換語言時重新套用所有 `[data-i18n]` 靜態文字，並重新渲染當前畫面的動態內容（選件卡片、事件敘述、雷達圖標籤、結果文字）。

### 音效（`js/sound.js`）
用 Web Audio API 即時合成音效（點擊、階段通過/失敗、發射、任務成功、解鎖成就），不需要任何音效素材檔，之後有正式音效素材再替換。

### 新手教學（`js/tutorial.js`）
角色 **ORBIT**（AI 助理，活潑吐槽調性），採劇情對話框穿插在實際畫面裡引導，而非一次講完的說明頁：
- 首頁：自我介紹＋任務總監身份說明
- 事件畫面：解釋場地事件的意義
- 選件畫面：解釋預算/質量雙重限制與部件分類
- 模擬畫面：說明 5 階段流程
- 結果畫面：解釋雷達圖與成就

每個畫面只在玩家「第一次」看到時觸發一次（存進 localStorage），可跳過單句或直接跳過全部教學。

### 首頁與設定
首頁三個入口：開始遊戲／成就展示／設定。設定頁目前有：語言切換（中/英）、音效開關與音量、重置進度與成就。成就展示會列出全部成就，未解鎖顯示「尚未解鎖」灰階，已解鎖顯示圖示與名稱。

## 15. 火箭飛行動畫（模擬畫面）

視角固定在畫面正中央，火箭本身不左右上下移動，而是背景場景（一個遠高於可視區域的捲動長條）往下捲動來製造「持續飛行」的感覺：
- 場景由上到下依序是深空（星空＋太陽系九大行星，色塊代表，含土星環）、大氣層漸層、雲層、地面
- 每個任務階段判定時，火箭先「嘗試」飛到該階段的中點（此時保持傾斜擺動＋噴射尾焰動畫），判定通過就繼續飛到該階段的完整檢查點高度並暫停尾焰；判定失敗則在當下位置爆炸（🚀 換成 💥），後續階段直接標記跳過
- 階段判定邏輯（margin／機率）完全不受動畫呈現方式影響，兩者已解耦

## 16. 劇情戰役模式（漸進式教學關卡）

取代「一開始就丟出全部機制」的做法，改用 4 個劇情關卡讓玩家一步步掌握遊戲內容，破完全部關卡才解鎖自由遊玩（現有的隨機事件＋完整機制＋成就系統）。玩家扮演新上任的指揮官，第一~三關是 ORBIT（訓練官）帶的模擬訓練，第四關才是真正的太空任務。

### 4 關對應真實火箭生命週期

| 關卡 | 對應真實階段 | 新引入機制 |
|---|---|---|
| 第一關 | 任務概念、軌道、子系統設計 | 任務目標＋軌道選擇、火箭＋4 個子系統（電力/通訊/科學/結構） |
| 第二關 | 推進系統設計 | 燃料類型＋填充量 |
| 第三關 | 環境測試 | 場地事件（**固定抽到太陽閃焰**，方便寫劇情），跟第一二關機制疊加 |
| 第四關 | 整合、發射、運作 | 完整機制（等同自由遊玩），劇情上是真正的任務 |

技術上用 `getCampaignFeatures(level)` 這個 feature flag 函式控制每關開放哪些機制（`orbit`/`fuel`/`events`/`forcedEventId`），`activeStagesForFeatures()` 依此決定要跑哪幾個任務階段（例如第一關還沒有燃料，直接跳過軌道插入判定）。自由遊玩（`campaignLevel = null`）則全部機制皆開放。

### 任務目標與軌道配對

任務目標（科學實驗／遙測／通訊／氣象觀測）在選件前隨機指定並揭露（跟事件卡同一套呈現邏輯），各自對應「正確」軌道：

| 任務目標 | 正確軌道 | 理由 |
|---|---|---|
| 科學實驗 | 低軌 LEO | 近地環境做微重力實驗 |
| 遙測 | 低軌 LEO | 需要近距離、高頻率掃描地表 |
| 通訊 | 同步軌道 GEO | 需要固定覆蓋同一地面區域 |
| 氣象觀測 | 同步軌道 GEO | 需要持續盯著同一區域 |

玩家自行選擇低軌／同步軌道（不受任務目標限制，可以選錯）：
- **低軌**：預算 100 C，無額外門檻
- **同步軌道**：預算 140 C，但發射階段可靠度門檻 +20（50→70），跟事件的門檻加成用同一套機制**疊加**而非互斥

### 「用結果教訓，不用介面鎖死」的設計原則

刻意不做 UI 層級的鎖定（例如不會把「不能選」的選項直接灰掉），而是讓錯誤選擇在模擬時得到對應的必然後果，並在結果畫面顯示專屬失敗原因：

- **輕型火箭 + 同步軌道** → 發射可靠度 60 vs 門檻 70，margin = -10，套用既有的「margin<0 必敗」規則，失敗原因自動顯示「火箭可靠度不足（數值 60，需要 70 以上）」，不用額外寫邏輯
- **軌道與任務目標不匹配** → 任務運作階段直接標記必敗（不透過數值判定），顯示專屬原因：「衛星軌道與任務目標不匹配：{任務目標}需要{正確軌道}，但選擇了{實際軌道}，導致任務無法達成」

### 技能點數與技能樹（節點內容尚未定案，存檔欄位已保留）

每次劇情關卡**成功**過關，依該局雷達圖分數（僅計算已解鎖機制對應的軸，平均分數 ÷ 20，至少 1 點）發放技能點數，永久存進 localStorage。技能樹分類直接對應關卡結構：

- **設計類**（對應第一關）
- **推進類**（對應第二關）——例如「毒性物質危害處理設施」解鎖聯胺燃料
- **環境應變類**（對應第三關）
- **整合飛行類**（對應第四關／完整任務）

節點效果走「解鎖類」而非數值加成（避免破壞已調好的取捨平衡），例如解鎖新燃料、解鎖预覽資訊、解鎖保底機制等。具體節點清單與解鎖成本尚未定案，UI 也還沒做，`storage.js` 已預留 `skillPoints`／`unlockedSkills` 欄位與對應的存取函式。

### 新手教學對話（劇情化，暫緩）

目前的 ORBIT 教學仍是單向對話框（見第 14 節），使用者希望之後改成有分支選項的劇情對話，但明確表示**先做遊玩內容本身，劇情呈現之後再做**，目前先維持現有的單向對話框機制。
